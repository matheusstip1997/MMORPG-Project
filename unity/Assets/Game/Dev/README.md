# Prediction dev scene (backlog D1)

`PredictionDev.unity` connects to a locally running GameServer, predicts your character with reconciliation,
interpolates every other entity, and draws them with the M1 placeholder art (see Visuals below) under the 45-degree camera.

Controls: **WASD** move (screen-relative), **mouse** facing, **C / V** turn the camera (placeholder keys, R-2.2-05).
The status line at the top shows the server tick, input ack, pending inputs, corrections and the last error.

## Run it

1. In PowerShell at the repository root, make a dev ticket secret and start the server with it (the server takes base64,
   `DevConnect issue` takes hex; both are the same 32 bytes):

   ```powershell
   $bytes = [byte[]]::new(32); [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($bytes)
   $env:MMORPG_TICKET_SECRET = [Convert]::ToBase64String($bytes)
   $env:MMORPG_DEV_TICKET_SECRET = ($bytes | ForEach-Object { $_.ToString('x2') }) -join ''
   $env:MMORPG_TICKET_KEY_ID = "1"; $env:MMORPG_REALM_ID = "1"; $env:MMORPG_GAME_PORT = "7777"
   $server = Start-Process dotnet -ArgumentList 'run --project src/GameServer' -NoNewWindow -PassThru
   ```

2. Right before pressing Play (tickets are single use and expire after `NetSecurity.TicketLifetimeMs`, 60 s), in the
   same PowerShell window:

   ```powershell
   dotnet run --project src/Tools/DevConnect -- issue --port 7777
   ```

   It writes `unity/UserSettings/DevTicket.json` (git-ignored). Issue a new one for every Play.

3. Open `Assets/Game/Dev/PredictionDev.unity` and press Play. Stop the server with `Stop-Process $server.Id`
   (or Ctrl+C in its window).

To feel the reconciliation, add latency or loss with a tool such as clumsy (Windows) on UDP port 7777: the capsule
should move at once, and the corrections counter should stay at 0 while you walk; dropped frames show up as small,
smoothed corrections.

The scene is generated by `Editor/DevSceneBuilder.cs` (menu **MMORPG / Dev / Rebuild Prediction Dev Scene**); change
the builder instead of editing the scene by hand. Config comes from `data/tables` (`StartingValuesM1`,
`ClientPrediction`, `ClientCamera`), read with the same rules as the server.

## Visuals

Entities show the `EntityVisualDef` row of their visual id (`data/tables/EntityVisualDef.json`), loaded through
Addressables (in the editor straight from the AssetDatabase, no content build needed). The local player uses the
`Local Visual Id` of `EntityViews` (default `warrior`: also `archer`, `mage`, `assist`); other players and monsters use
the `visualId` of the `ClassDef` or `MonsterDef` row their spawn names, or the defaults next to it. A missing id or
prefab shows the capsule.

Monsters (backlog F): the server spawns one `m1.demon` at each `SpawnPoints` marker of the sample world. The nearest one
stands a few meters past the city gate (east of the spawn, 32 m away, just outside the interest area): walk toward the
gate and it appears. Monsters stand still until the monster AI exists; one that dies respawns after 30 s. The status
line also shows your HP, MP and stamina from the snapshots.

Keys of the fake action source (stand-in for D2's action machine, placeholder timings, not ActionDef values):
**1** attack (startup, active, recovery), **2** channel, **F** flinch, **G** stagger, **K** death, **L** back to
locomotion.

The prefabs, animation sets and Addressables entries under `Assets/Content/Visuals` are generated by
`Entities/Visuals/Editor/EntityVisualPrefabBuilder.cs` (menu **MMORPG / Visuals / Rebuild Visual Prefabs**, or batch
`-executeMethod Game.Gameplay.Entities.Visuals.Editor.EntityVisualPrefabBuilder.Build`). On a fresh Library the
VRM and glTF importers can fail once ("Parameter name: Shader": the model was imported before its shader), and Unity
keeps the failure; the characters then have no humanoid bones and hold no weapons. `FailedModelReimporter` (in the
builder's file) imports such a model again right after its import pass, and `EntityVisualTests` and the builder repair a
Library that kept the failure from before.

The art under `Assets/ThirdParty` (and the LiteNetLib DLL) is in Git LFS. A new worktree can hold LFS pointer files
instead (Unity then stops with `CS0246 ... 'LiteNetLib'`, and the models fail to import): run `git lfs pull` (or
`git lfs checkout` when the objects are already in the local LFS cache) before the first Unity run.

## QA smoke run

`Qa/` holds a scripted run of this scene from the login screens (walk to the demon, kill it, Arrow Shot at a wall, wait
for the respawn) with a screenshot and a JSON result per step: `tools/qa/Run-QaSmoke.ps1`, see `tools/qa/README.md`.
