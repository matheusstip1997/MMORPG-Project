## 8.2 Transaction catalog (all atomic, idempotent, audited)
| Operation | Owner service | Atomic steps |
|---|---|---|
| Sell at outpost | PriceService + Inventory | remove items, add gold, register sales (class 1) |
| NPC vendor purchase | Inventory | remove gold (destroyed), add item (class 1); M3 (WP-M3-2): molds and tools as one new instance in the Safe bag equipment area, its id and the instance counter in the same transaction |
| Trade | Inventory | validate both sides, swap items and gold |
| Auction/shop sale | Inventory + FeeService | escrow item, pay seller minus fee, deliver item |
| Consumable use | Inventory (+ `Items/ConsumableUse`, M3, WP-M3-3) | at the use action's effect point: remove one unit (reason `ItemUsed`, class 2, op key `use:{run}:{entity}:{connection}:{requestId}`), raise toxicity or satiety (the same character save), start the cooldown; heal, MP and status in phase 6; answered after the commit (spec 3.4) |
| Harvest | Inventory (+ `World/Nodes/HarvestService`, M3, WP-M3-5) | at the harvest action's effect point: the yield rolled from a per-harvest seed of the world's harvest stream; a yield that does not fit is refused `BagFull` and the node stays available; else add it (reason `Harvest`, class 2, op key `harvest:{run}:{entity}:{connection}:{requestId}`) and deplete the node at once on the world thread (two harvesters in one tick: the lower entity id wins, the other gets `NodeDepleted`); `Harvested` and the `HarvestResult` only after the commit; a crash before it loses the add and the node's state (nodes are memory only) |
| Craft / refine / convert / enchant | ForgeEngine + Inventory | consume reserved materials (M3: `InventoryService.Reserve` holds them in memory, nothing written; `TryRemoveReserved` consumes them in the operation that creates the output; released on cancel or when the session ends, WP-M3-2), create or modify item, log seed; M3 (WP-M3-6): `Crafting/ForgeService`, one class 2 operation per finish asking for a save at once (`SaveReason.Craft`): the inputs consumed (`{key}:in`), the output made (`{key}:out`) and one `craft_ops` row (operation key `forge:{character}:{seed}`, the seed, the quality and rarity) in the character save's transaction; a failed conversion consumes its inputs and makes nothing (`ConvertFailed`, a sink); answered (`ForgeResult`) and published only after the commit; a crash before it leaves every input in the database and shows nothing |
| Gem socket | GemService + Inventory | consume gem, update item, recompute stats |
| Contract accept / complete | Contracts + Escrow | lock customer assets, deliver output, pay crafter minus fee |
| Run claim | RunService | step bonus, forfeit penalty, exp per member by contribution (class 2) |
| Death drop | Loot + Inventory | move Normal bag into persisted loot bag |
| Loot pickup / return | Loot + Honor | move items, set/clear stolen mark, honor change |
| Laundering | Fence + Inventory + Honor | charge fee, clear mark, lower honor |
| Sentence | SentencingService | honor reset, confiscate, jail, audit |
| Release | JailService | return items (stolen to original owner by mail) |
| Skill learn / upgrade / evolve / respec | SkillTree | check, adjust nodes and points, recompute stats. M2 (WP-M2-5): `SkillTreeService` applies it and asks for a save at once; that save writes the points in the row with the `skill_ops` audit row (the op key `skill:{run}:{entity}:{connection}:{request}`), the learned set and the hotbar in one transaction; answered and visible only after the commit |
| Class advance | Skills | change class, unlock tree, remap skills. M2 (WP-M2-5): the same save path; `characters.class_id` changes with it, one advance per tier and character (unique index) |
| Job pick | Jobs | WP-M3-1 (spec 5.1 M3 decisions): `JobService` checks it (gate, `CheckPick`, combat, room), writes the record and grants the starter items through `InventoryService.TryAdd` (key `jobStart:{character}:{job}:{n}`), and asks for a save at once; that save writes the `job_progress` record, the `job_ops` audit row (op key `job:{run}:{entity}:{connection}:{request}`) and the items in one transaction; answered and visible only after the commit; one pick per slot and character (unique `job_progress_slot`, `job_ops_one_pick_per_slot`: permanent) |
| Job tree learn, respec | Jobs | WP-M3-7 (spec 5.1 R-5.1-04, `docs/design/job-trees.md`): `JobService` checks it with the shared `JobTreeRules` (a learn: the job held, the row gate, the prerequisites, the max level, the points, no combat refusal; a respec: something learned, out of combat and an action, no harvest or forge session through `IJobActivityGate`), applies it to the working record and asks for a save at once (`SaveReason.JobTree`); that save writes the `job_progress` points, the whole `job_nodes` set and the `job_ops` row (op 2 learn, 3 respec; node, levels, points before and after; op key `jobTree:{run}:{entity}:{connection}:{request}`) in one transaction; answered (`JobTreeResult`) and read by `IJobBonusQuery` only after the commit; a respec gives back every point at once (free) |
| Instance entry/exit | WorldManager | remove, validate cap, add, persist location |
| Guild feature purchase | Treasury | debit restricted ledger, destroy gold, grant feature |
| Siege resolve | SiegeService | ownership change or treasury theft, cooldown |
| Create/delete character | Accounts | slot check, name uniqueness, soft delete |
| Arena match end | Arena + Rating | update ratings, apply penalties, return players |
| Season close | SeasonService + Unlocks | rank rewards and skins granted once (idempotent) |

## 8.3 How the systems talk
Pattern: **commands** go through service interfaces and return results; **facts** are published as events.
| System | Calls (commands) | Emits / consumes |
|---|---|---|
| Net / Session | Persistence, WorldManager, Sentencing | emits Session events |
| World / Interest | Visibility, Regions | emits region and instance events |
| Combat | Stats, Skills, PvpRules, Visibility | emits Damaged, Killed, Died; consumes nothing from gameplay |
| Stats | none (data) | emits StatsChanged; consumes skill/gear/buff changes |
| Progression | Skills, Inventory (rewards none) | consumes Killed, quest, craft events |
| Items / Inventory | Persistence | emits item and gold events; called by all value systems |
| Economy | Inventory, SpawnController | consumes Killed, Harvested; emits price/demand events |
| Crafting / Gathering | Inventory, Stats, StolenMark | emits Crafted, Harvested... |
| Contracts | Escrow, Inventory, FeeService, ForgeEngine | consumes Crafted for portfolio |
| Quests / Runs | Inventory, Exp, Party | consumes Killed, deliveries |
| Law (PvP/Honor/Arrest) | Inventory, WorldManager, Honor | consumes Killed, Died, Detected, item events |
| Guilds | FeeService, WorldManager, Treasury | consumes FeeCharged, crimes, region events |
| Social | WorldManager, Mail | emits PartyChanged |
| Arena | WorldManager, Party, StatBlock, Unlocks | emits match and season events |
| Telemetry | none | consumes everything |

```
Gameplay input -> Combat -> Killed/Died ------------------------> EventBus
   EventBus -> Exp/Achievements/Quests/Demand/Loot/Honor/Reputation/Telemetry
   Loot/Quests/Crafting/Contracts/Trade --calls--> InventoryService / EscrowService / FeeService
   Law --calls--> SentencingService -> Inventory + World + Honor
   Guilds --calls--> Treasury, WorldManager(sieges)
```
